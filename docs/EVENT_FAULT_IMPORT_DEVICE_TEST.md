# PR #41 – Ereignisse und Störungen der eigenen Fahrerkarte

Ausgangsbasis: bestandene PR-39-Test-App, Schema 9, Version 40105. Update: Schema 10, Version 40106, gleiche Paketkennung und Testsignatur. Bei vorhandener **FahrerTagebuch Test** ausschließlich `02-FahrerTagebuch-Test-Update.apk` installieren. Nicht deinstallieren oder Daten löschen. Die Ausgangs-APK ist nur für eine neue, getrennte Testinstallation vorgesehen.

1. **Update und Altdaten:** Ohne Leser das Update installieren. Profil, alte Imports, Kartentage, Fahrzeugnutzungen und Kontrollen bleiben verfügbar. Eine vor dem Update gespeicherte Übernahme öffnen: „Gespeicherte Daten ansehen → Fahrerkarten-Details → Ereignisse und Störungen“. Für diese Übernahme sind keine gespeicherten Ereignis-/Störungsdaten verfügbar; neu gelesene Daten dürfen später nicht hineinkopiert werden.
2. **Eigene Karte automatisch lesen:** Leser anschließen, eigene Karte einlegen, gegebenenfalls Android-USB-Zugriff bestätigen. Keine neue Erstbestätigung und kein Speichern-Knopf. Kartentage, Fahrzeugnutzungen und Kontrollen bleiben nutzbar. „Ereignisse und Störungen“ der neuen Übernahme öffnen: aufgezeichnete Meldungen mit ihren vorhandenen Zeitpunkten/Fahrzeugangaben oder ausdrücklich keine aufgezeichneten Ereignisse bzw. Störungen. Beides kann korrekt sein. Unbekannte Zeiten bleiben „nicht angegeben“; keine erfundenen Dauern oder Verstoßbewertung. Keine Meldung eigens für den Test erzeugen.
3. **Wiederholung und exakter Stand:** Karte herausnehmen und erneut einlegen. Keine Leseschleife, keine zusätzlichen identischen Quelldaten. Ältere und neue Übernahme im Importverlauf einzeln öffnen: Die ältere behält ihren damaligen Stand, die neue zeigt ihre eigenen Daten. Bei unverändertem Karteninhalt meldet der Wiederholungslauf, dass die Daten bereits vorhanden waren.
4. **Neustart ohne Leser:** Leser entfernen, App vollständig beenden und wieder öffnen. Profil, ältere Daten sowie die neue Ereignis-/Störungsansicht bleiben verfügbar.

Wenn eine zusätzliche Datei auf der konkreten Karte nicht lesbar ist, muss eine verständliche Teilfehlermeldung erscheinen; die anderen erfolgreich gelesenen Daten bleiben verfügbar. Bitte in diesem Fall nur die Meldung und Kartengeneration nennen. Keine Rohkartendaten oder unmaskierten Nummern versenden.

Automatische Tests decken synthetische Gen1/Gen2/Gen2V2-Dateien, Gruppengrößen, Metadaten und vollständige 24-Byte-Datensätze, unbekannte/invertierte Zeitpunkte, leere/fehlende/ungültige Dateien, unabhängige Lesefehler, Abbruch, eigene/Fremd-/Ersatzkarten, Deduplizierung, Transaktions-Rollback, exakte Wiederöffnung und Migration 9→10 ab. Die manuelle Prüfung bestätigt ausschließlich die vorhandene Geräte-/Leser-/Kartenkombination. Tageszeitleisten-Marker, weitere Kartenabdeckung und Fachauswertung sind nicht Teil dieses Schritts.
